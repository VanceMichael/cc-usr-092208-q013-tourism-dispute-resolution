# 跨境旅程争议协商

协同处理入境旅程中跨服务商、跨币种的履约争议和退款。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括入境游客、境外组团社、国内地接社、景区、承运人、支付机构与调解人员。

资料所依据的领域事实如下：

- 活动聚焦入境旅游企业经营难点与行业流通堵点
- 跨境旅游和跨境支付经验被作为案例分享
- 参与方希望把便利化举措转化为落地成果
- 航班变化等履约事件会引发跨服务商、跨币种的多笔退款
- 游客需要始终看到未决项目与下一责任方

## 案件模型

`contracts/case.schema.json` 规定单件争议案件的归并资料结构，`fixtures/case.json` 保存一例化名示例：某入境团因航班变化取消境内航段，游客就取消航段与部分履约的景区行程提起协商。`domain` 包以原合同和实际履约事件为基础归并以下材料：

- 多语种陈述、票据与服务确认等证据、汇率时点、各方责任意见
- 同行人拆分、部分履约、证据补交、时限暂停、调解失败、支付退回等有序事件

在此之上提供以下能力，均不替代人工裁决：

- `FindDuplicateClaims` 自动发现疑似重复索赔并附理由，仅供调解人员复核
- `PendingView` 向游客展示未决项目与下一责任方
- `MaterialsFor` 限定企业只访问与自身服务有关的材料，支付机构只访问票据
- `ProposeSettlement` 生成逐项可解释的和解方案，引用合同、履约事件、证据与汇率时点作为依据
- `VerifyExecution` 核对退款、代金安排和书面结论是否真正执行到位

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束，并校验案件资料的引用一致性与事件顺序。运行项目自带测试即可检查这些基础资料能够稳定读取：

```sh
go test ./...
```

仓库不保存账号、密钥、连接串或真实身份信息。
