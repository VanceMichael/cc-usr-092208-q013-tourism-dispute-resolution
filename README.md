# 跨境旅程争议协商

协同处理入境旅程中跨服务商、跨币种的履约争议和退款。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。参与方包括入境游客、境外组团社、国内地接社、景区、承运人、支付机构、调解人员，以及作为协商服务运营方的区域文旅合作方。

## 问题背景

入境团队游因航班变化取消一段行程时，境外组团社、国内地接、景区、承运人和支付机构往往各自计算责任。游客收到多笔不同币种退款，却仍不知道哪些服务尚未解决。协商服务以原合同和实际履约事件为基础，归并多语种陈述、票据、服务确认、汇率时点和各方责任意见，自动发现重复索赔，但不替代人工裁决。

## 处理流程

`workflow` 字段按顺序记录主流程阶段：争议登记 → 证据归并 → 责任意见汇总 → 重复索赔核查 → 和解方案生成 → 人工裁决确认 → 退款与代金执行 → 执行核对与结案。同行人拆分、部分履约、证据补交、时限暂停、调解失败和支付退回作为流程中的分支事件，必须与主流程保持清晰顺序。

## 可见性与执行原则

- 游客始终能看见未决项目与下一责任方。
- 企业只访问与自身服务有关的材料。
- 调解人员可生成逐项可解释的和解方案。
- 所有退款、代金安排和书面结论都要核对是否真正执行。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、约束和流程顺序。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
